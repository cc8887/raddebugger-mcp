## Unicode 与 UE 结构化值读取修复

新构建继续固定同一 RAD 上游提交，wire bridge 仍为版本 1：后端 SHA-256 为 `bb7cd7dea509b8ef7ba61d0244069714e428a49c1ab843280b79e6aa35300101`，完整补丁 SHA-256 为 `7100d1288a8e31fa7af79d5b9a8890d57b15c56b8c44e9aab67f6c504ce1f266`；扩展代码 SHA-256 不变。上面的分离修复构建与旧测试计数是历史证据，不代表当前构建身份。

根因是 FString 视图给出的 UTF-16 单元数量，在转为 UTF-8 后再次被当作字节数量裁剪：两个中文字符可能只剩第一个，或裁到 UTF-8 序列中间导致 IPC 严格解码失败。修复在源编码单元上进行有界读取，并严格验证 UTF-8/UTF-16/UTF-32；最终 512 **字节**显示上限只切在完整 UTF-8 序列边界。截断和非法编码均有显式状态与消息，不以 `ok=true` 冒充完整值。未知长度指针的字符串扫描另有 4096 源字节预算。

新增 `rad_read_value` 从匹配 PDB 和数值内存探针结构化读取 FString、FText、TArray、稀疏 TMap；不调用目标函数，不依赖 UE 插件或编辑器 MCP。FString 取址显式禁用自动视图，防止空串的数据空指针被误当作对象地址。文本页按 UTF-16 单元续读；TMap 页按物理槽位续读、检查占用位图并跳过空洞，通过 PDB 获取实际槽位大小。FText 仅支持经字段/类型验证的 localized string 与 generated display string，未知历史明确失败。

真实 UE 的额外检查发现，通用 FText 结构展开仍可能把共享对象的未定型字节存储当成文本，出现显式编码错误，而实际显示 FString 与结构化 FText 均正确。保留该失败记录，不放宽编码检查。常规 `rad_evaluate(FText)` 现复用验证后的语义读取路径，单独保留原生结构诊断；`raw(...)` / `typeof(...)` 不改写。源代码中共享控制块的引用计数与 `TTypeCompatibleBytes::Pad` 与该现象吻合，但没有把具体内部错误叶节点推断当成运行时定位结论。

该实现限定于显式 UE4.26 Win64 布局：保留对象指针身份与类型，不冒称任意 Actor 的完整反射展开。单次读取最多 512 探针 / 60 秒；进程、线程、帧与停点代际在每个探针及最终结果处检查，非 direct-process-read 的后端拒绝使用。仍不等于整个进程的原子快照。

## 修复的实际问题

1. 原始 Win32 socket 绑定全部网卡且没有会话认证，socket 还会被启动的目标继承。本版本使用回环绑定、每会话令牌和不可继承的 socket。
2. 上游把 WSARecv 的一次完成当成完整消息。本版本对每个连接的请求做有界重组，Python 客户端按帧长读取回复。
3. 无图形目标缺少 comdlg32 链接依赖，桥接构建补足该依赖。
4. IPC 的进程/线程参数原先不能根据数字解析；文件路径、`--` 后的表达式和配置 ID 也需要准确传递。本版本修复并实际验证。
5. 控制端的符号名查询原先使用非阻塞异步匹配，首次查询可暂时返回地址 0，导致放行执行后错过函数断点。本版本对每次控制端求值上下文使用共享的 5 秒符号查询截止时间；UI 保持非阻塞。模块装载时会创建新的上下文。
6. attach 命令可在 Process 实体建立前先增加 run_gen。等待器现在不会把这个过渡状态误报为“进程已退出”。
7. Dump 是后端中的离线逻辑进程，关闭时不应使用 Windows live-process detach；本版本会释放后端而不尝试原生分离该逻辑进程。
8. RAD 自动保存项目时可能覆盖 MCP 刚写入的目标配置。现在使用独立输入文件和原生配置命令，只替换目标节点，保留活动项目与断点 ID。
9. 原始求值接口可能在异步内存缓存未就绪时返回看似有效的 0。MCP 求值现在绕过进程页面缓存、清除缓存的计算值，并在读取失败时明确标记 `ok=false`。Dump 读取也要求请求区间完全被存储的内存范围覆盖，不能把部分覆盖当作完整成功。
10. 核心帧循环在引擎事件追加命令后，可能因迭代器到达末尾时被清空而再次从队列头开始，导致重复状态回复甚至重放执行命令。补丁保留最后消费的命令游标；不放宽协议解析器的重复字段检查。
11. 求值解释器可能在消息列表被复制之后才附加除零等错误；IPC 现在另外检查实际解释器状态。普通运算也拒绝将类型当作数值，避免歧义 C 风格转换被解释成按位与后悄悄返回 0。类型比较路径保持不变。
12. 单步停止后直接分离未完成待续行事件，可令目标以 `0x80000003` 退出。现已按目标 PID 续行，并保留分离后仍有效的独立线程句柄恢复执行；失败保留可重试状态，补充直接分离回归与真实游戏 PIE 复验。
13. FString 的 UTF-16 长度被误作 UTF-8 字节长度，导致中文截断或 IPC Unicode 解码错误；现已按源编码有界读取、严格验证、按 UTF-8 边界限制显示，并提供独立的结构化文本与稀疏容器读取工具。
